# 流程内SetAudioState阅读支持

优先解析现有配置并验证正文顺序，资产和实际音频播放继续保留未核验状态。

## 来源与代表任务

扫描flowstate可解码动作得到120处SetAudioState，共42种参数值组合；均为AudioConfig.Group和AudioConfig.State两个非空字符串。此前项目只在任务阅读投影支持这类参数，流程动作解析仍拒绝。

选定121000038《燃烧的心》。流程“剧情_2_4_七丘主线_下半_2_1”按动作数组先将story_music_2_4_B_M2_6_06_state设为none，再PostAkEvent、DestroyEntity、ShowTalk，最后设为after。参数中没有分支、对白或流程引用。解析保留动作数组和原对话控制结构，不根据音乐状态猜剧情。

## 通用实现与边界

复用validate_reading_effect对AudioConfig严格校验，新增流程外层字段校验。仅阅读模式允许同步或缺省Async，外层Name、Params、ActionId、ActionGuid、Async；额外条件字段、嵌套数据、非字符串状态、异步均拒绝。严格模式继续拒绝，不把未模拟的音频行为称作实际执行成功。

每次调用留在action_log及audio_state_change证据中，不生成台词，不改说话人，不选择选项。TXT仅展示原对白、选择及必要缺口。覆盖报告使用相同校验，已支持的形状不再误报未知流程动作。组合项/选项的原有顺序检查维持。
