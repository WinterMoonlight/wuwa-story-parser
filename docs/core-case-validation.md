# 核心案例：撞金止行阵（139000029）

## 选样依据

`python run.py scan-mainline` 扫描全部 85 个 Type=1 和 50 个 Type=15 候选，输出 outputs/主线结构扫描.json、主线结构扫描.md。评分为节点类型数×4 + 条件类型数×2 + 流程动作类型数；对白编辑器 Name（如“对话2”）不计为动作。

核心案例选自 Type=1 且回顾与显式流程引用完全一致的任务。《撞金止行阵》在这个可核验子集中评分最高（62）：73 个节点、6 类节点、10 类步骤条件、18 类流程动作、24 段回顾流程。并非宣称它是全库最大的任务：分数更高的候选存在回顾与任务引用差异，需要先解释归属。

## 本次实现

- 校验任务父子关系、重复 ID、孤立父节点与父链循环，保留复杂节点结构。
- 使用 PlotHandBook 提供的有序列表构建阅读路线，要求显式流程集合完全一致且状态存在；不执行任务引擎的并行/条件调度。
- 任务动作中明确引用的 PlayFlow 由回顾顺序覆盖；允许的玩法动作保留为证据，条件按已完成记录。未知动作继续阻塞。
- ShowCenterText 导出为画面文字，防止丢失非对白叙述。
- 无条件循环菜单再次出现时选择尚未选过的选项；无新选择进展或选项耗尽仍无法退出时报错。
- 所有选项分支均检查文本引用、动作类型和 JumpTalk 目标，包括未选分支。
- 每组 ShowTalk 分开记录覆盖信息；同一场景多组对白不混用选项键。
- 对白动作与选项共存时，仅接受不改变文本、身份和跳转的有限视觉动作；其他情况仍报错。

## 导出验收

命令：`python run.py export-task --quest-id 139000029`。

成果：outputs/任务样本/139000029_撞金止行阵.json 和同名 TXT。

24 段流程全部覆盖，27 组 ShowTalk 完成引用检查；正文共 321 个事件：266 条对白/叙述、54 次选择、1 条画面文字。没有缺失文本。玩家名统一为漂泊者，性别分支选 Female，保留 raw_text。

开头为炽霞带漂泊者到攀花处吃早餐，后段涉及鉴心、寻人及莽吉柿，最后包含任务关联的功能引导对白。部分流程键仍带上一幕名称，但同时被本任务与回顾配置引用，因此保留，不能按文件名猜测归属并删除。

鉴心场景 `_1_23` 的 TalkId=20 是循环提问菜单：默认依次选择索引 0、1、2、3、4，最后退出。测试将第一次选择改成索引 4 时，正文变短但最终文本 ID 一致，证明不是将所有选项文本机械拼接。

本阶段当时测试共 17 项通过（后续诊断测试加入后为 18 项，最新记录见 [progress.md](../progress.md)），包含核心菜单退出、替代路线、未选分支坏跳转、无退出循环拒绝、孤立/循环父链，以及原有姓名与分支回归测试。
