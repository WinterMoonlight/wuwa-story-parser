# 捕梦于神秘园中：变量与条件阅读路线

## 本轮实现范围

三个子agent分别核查变量语义、分支提示归属和writer到selector的边界，主agent整合。variables模块仅支持显式作用域内的Boolean常量SetVar及Eq比较，未赋值为unknown，不能当false。Self与Global隔离，没有Global作用域则拒绝。普通解析路径仍不支持SetVar，只有受限条件阅读器创建变量环境后才执行所选选项的赋值。

conditional_recap只处理可程序验证的形状：两个互补Boolean条件槽、同一Self变量、唯一writer的PlayFlow节点和相同Sequence父节点、回顾writer前唯一提示、writer紧接连续且可唯一归属的分支提示区段、两个选项各一个精确常量赋值。解析失败不提交环境，不根据任务ID、变量中文名或流程数字特判。

读取writer后只执行选中的选项，再用其变量值计算条件。branch_recap用精确TidTip→唯一任务节点→条件槽归属标注具体回顾出现位置；只给节点直接引用的flow归属，不把所有后续flow都当该分支。排除段落原配置与事件保留在JSON的unselected_original中，独有正文仍可在附录候选材料找到。

## 为什么不能照抄整个回顾

原entry[6]是1/2选择；[7..8]属于左路；[9..14]属于右路，其中1/17出现两次，分别属于不同分支。

- 默认选择左路：变量false，保留entry[8]的1/17，排除entry[12]的1/3和entry[14]的另一次1/17。
- 验证选择右路：变量true，排除entry[8]，保留entry[12]的1/3与entry[14]的1/17。

这按具体出现位置选择，不是把同名flow一律去重。每条路线均只出现一次汇合对白，已选选项与正文一致。

## 尚未证实的边界

writer节点22和selector33共享Sequence28，但该父记录没有有序Children；回顾先后能证明配置阅读顺序，不能单凭节点数字证明运行时相邻。31条直接关联配置未找到同变量改写，但资产内隐式调用仍未知。另有不在本任务回顾、未找到精确调用的1/14写true，不额外执行它，也不宣称其永远不会触发。

因此TXT明确提示：此路线假设所选变量值未被其他交互覆盖。JSON记录runtime_route_verified=false、条件结果、变量作用域、赋值前后及分支来源。异步8/1不插入有序正文；其他任务动作、玩法和资产缺口继续保留。回顾可读不等于实际完整任务路线。

详见[路线核查](capture-dream-route-investigation.md)与[writer边界](capture-dream-writer-boundary.md)。

## 验证

155项测试通过，含未知值与作用域、未选赋值不执行、精确提示归属、左右选项与后文一致、汇合对白只保留一次。最终批次20261117_023233_327940，对比20261117_022724_707911核对135对JSON/TXT：仅本任务恢复1段14事件，默认左路正文排除2个右分支片段共4事件（原文完整留在JSON，独有文字在附录可查）；其他成功段落与静态文字保持，TXT渲染一致，《来自毁灭的回声》不变。回顾阻塞任务32→31、阻塞段落69→68。分类、严格通过2及有文字任务132均不变，没有新增整任务验收。

未选段落的原缺文/未核验记录不累计为所选路线的段落缺口；完整来源仍保留。当前场景已按规则筛选，但全任务运行时顺序依旧未证实。
