# 批量阅读版姓名与文本类型核查

2026-11-17。此轮修正的是静态材料的显示归属，不改变路线选择和剧情顺序。

## 原因

reading_batch.inventory递归提取TidTalk、TidTalkOption、TidCenterText时，将display_name统一设为“说话人待核验”。此前已有的SpeakerResolver只供其他路径使用，因此许多能够查到的姓名没有显示。递归携带的WhoId还可能是选项外层NPC，不能直接拿来给玩家选项命名。

## 通用规则

|文字来源|类型与显示|证据边界|
|---|---|---|
|TidTalk|dialogue；自身WhoId对应的姓名|读取NameStringKey，回退BinData字段3；缺失或匿名保留问号|
|普通对话Options中的TidTalkOption|choice；漂泊者【选择】|不继承NPC，selected=false，不声称实际选择|
|TidCenterText|screen_text；画面文字|不赋予人物身份|
|QTE的Options|qte_result；QTE结果文字|不作为普通选择，不声称成功或失败已发生|
|SystemOption的Options|system_option；系统选项|保留系统选项性质|
|未识别容器内TidTalkOption|unknown_option；？？？|不强行猜为玩家|

普通选项容器覆盖已观察的Talk、Option、VisualNovelTalk、VisualNovelNarration、VisualNovelOption、AvgTalk、AvgNarration、PhoneMessage；旧式无Type容器还必须有Id和TidTalk/TextId。所有嵌套Actions重新判断自身文本类型，不沿用父选项身份。分支类别与文本类型分别保存，失败分支的选择仍属于失败材料。

静态提取不执行Begin/ChangeActor等演员变更，也不按遍历顺序解析匿名身份。只显示配置名，不把同一个匿名ID映射成固定人物。原始模板、文本键、来源路径、当前及继承WhoId、姓名表来源留在JSON；TXT使用女漂泊者和玩家名替换规则。
