# 阅读验收

阅读验收着重检查主线能否连续理解，覆盖任务的起因、主要过程、关键选择和后续承接。

## 检查内容

1. 核对任务首尾和章幕间衔接。对照任务前置、回顾提示和源调用，确认每处插入有可追溯的前后锚点。
2. 核对采用的对白和选项。确认选项与随后的对白属于同一配置路线，说明重复调用和可能发生的可选交谈。
3. 核对说话人、文字引用和渲染。原模板、配置角色和无法确定的身份可从 JSON 复查。
4. 对缺定义、演出、界面和复杂互动，检查原引用与略过说明是否一致。只说明有证据的内容与结果。
5. 检查对照批次中未修改任务的正文、选项和来源。记录核对的实际范围。

## 结论

| 结论 | 条件 |
|---|---|
| 可连续阅读 | 主干文字、所选路线、顺序和衔接均已核对 |
| 带明确缺口可阅读 | 主要文本可读，待核范围和位置有说明 |
| 仍是材料 | 缺少关键正文或必要顺序，尚不足以形成可读主干 |

`mainline_reading.status` 是程序输出的草稿状态。人工审查记录单独绑定任务 ID 与源 JSON、TXT 的 SHA-256。`accepted=true` 用于通过单任务人工阅读审查的记录。若需要章幕级验收，应同时检查该幕所有任务及相邻衔接。

使用 `export-review` 可以按已保存的审查记录生成阅读审查版。见[命令参考](commands.md#生成阅读审查版)。已有审查样例和专题证据见[文档目录](README.md)。
