# 任务节点与对白选择

解析器用数据库中能追溯的调用和条件来恢复阅读顺序。一份 TXT 采用一条有依据的阅读路线，JSON 保存原始动作、条件、选项和未采用的候选材料。

## 任务节点怎么进入顺序

| 配置 | 用来确认的关系 |
|---|---|
| `Condition.Type = PlayFlow` 和同节点的 `FinishActions.PlayFlow` | 当前流程作为完成条件，完成动作才会调用下一流程。相邻同步动作可提供局部先后。 |
| `EnterActions` 和 `FinishActions` | 区分进入节点和完成节点的动作。`Async=true` 的动作只提供调用位置，播放结束时机需单独核查。 |
| `Sequence`、`ParentNodeId` | 表明节点的层级和作用范围。扁平配置中的同级顺序需要回顾或依赖印证。 |
| `ParallelSelect`、`ConditionSelector`、`QuestFailed` | 保存并行、条件选择和失败分支的上下文。可达性或必经性缺证时，材料保留在 JSON。 |
| `AwakeEntity`、`DestroyEntity`、交互组件 | 结合精确地图和实体 ID，核对对白在哪个阶段可以触发。玩家可自行触发的片段在 TXT 标为可选。 |
| 回顾条目、任务提示键 | 在 `db_PlotHandBook` 中确定段落位置。恢复遗漏段落时还需核对准确的流程键和独立触发证据。 |

读取流程时按 `FlowListName`、`FlowId`、`StateId` 构造精确状态键。节点数字、数据库行次序和相邻状态编号都不足以给出阅读顺序。

### 配置示例

- **《千里卷戎旌》营地**（140000004）。节点 30 唤醒地图 8 的实体 140800001，节点 110 进入时销毁它。交互组件指向 1/11，回顾的“检查营地”位于 1/2 和 1/16 之间，因此把 1/11 列为这个阶段的可选交谈。玩家实际交互时刻仍由游戏决定。
- **《山雨欲来风满楼》旧屋**（189000005）。节点 203 调用昏迷对白后传送至副本 2525。玩家进入屋内范围后由节点 135 同步触发苏醒对白，节点 133 的离屋交互对应唯一回顾提示。这段按副本范围和回顾锚点放在两者之间。
- **乘霄山总回顾**。任务回放编组、任务前置链和唯一回顾提示都对得上时，才把章节总回顾分配给各原任务。可通过 `chapter_recap_order` 查每段原始位置。

## 对白选项怎么选

对话按 `ShowTalk` 中的文字和显式跳转推进。普通菜单首次进入使用索引 0，可用 `--choices` 覆盖。重访普通菜单时依次尝试尚未选择的选项；用尽后仍不能退出则记录阻塞。选项编号从 0 开始。

`PreCondition`、变量读写与 `FinishState` 可能改变可用选项或后续路线。兼容阅读模式只在已有条件规则或经过验证的备选路径下生成正文。自动改用备选时，JSON 记录原选择、改选依据与原错误；显式覆盖仍按指定选项处理。

`route.choices` 记录采用的选项及其所在组。用选择文件时，从该字段复制 `choice_key`，并为它指定选项索引。参见[覆盖选项的命令](commands.md#覆盖对白选项)。

## 章幕之间怎么排序

章幕目录来自任务的 `ChapterId`。连读索引用 `PreQuest` 和已核对的 `PreChildQuest` 建立前置关系，并与已核对的总回顾比较。`PreChildQuest` 指到具体子节点，索引据此给出阅读位置。章节树可提供缺少强制前置时的阅读连接，实际开启先后待核的位置会标明。

实现与字段的详细信息见[运行架构](architecture.md)和[语料格式](corpus-format.md)。
