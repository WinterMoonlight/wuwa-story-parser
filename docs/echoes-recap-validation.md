# 《来自毁灭的回声》回顾主干验证

2026-11-17，任务145000004。目标是先恢复可读的回顾主干，把选择放回对白；并未完成整个任务的运行时还原。

## 原来的问题与本次改变

原任务首先因EnableHostility动作不受支持而中断，同时存在8个任务独有、24个回顾独有引用。旧批量逻辑把全部文字退回静态材料，按候选/待核验分类展示，导致已知的回顾顺序和对白中的选择也被拆散。

新增recap_backbone降级路径：完整任务审核失败后，若回顾表有唯一记录、唯一条目数组，就按原条目顺序逐段执行已有对白解析器。一个段落不支持时，丢弃该段临时状态、在原位置留缺口，继续下一段。每段独立演员槽位与选项历史；仅只读姓名表复用。未知动作没有被当作无效果跳过，严格模式不变。

回顾中的重复条目按原次数保留。可解析段落使用既有首个无条件选项、循环首次未尝试选项策略，选择紧随上下文。未选择文字和未定位的任务独有内容在附录保留，不自动追加成已发生剧情。

## 重复流程的来源

`剧情_1_3_世界_黑海岸_去除污染_11_2` 与 `11_3` 的14条文字引用序列一致，包括姓名ID与选项类型。原任务节点581是ConditionSelector：CheckPlayerGender女对应节点580的11/2，男对应节点582的11/3。两份配置的背景图分别包含Female/Male；还存在CaptionParams.TotalTime、内部TextId、动作标识及TalkOutline差异。

回顾引用11/2，符合本项目女性漂泊者设定。阅读稿不再把11/3相同文字重复拼接为后续剧情。JSON保留源引用、文字记录、散列及动作不相等标记；[重复核查文件](../outputs/回顾主干验证/重复流程核查.json)还保存完整差异和性别选择器证据。

通用折叠规则并不根据文件名猜性别，也不宣称两个流程等价：仅当非回顾额外来源的整组文字键、正文、类型和说话人序列相同，才省略重复展示。回顾里本来重复出现的流程不会折叠。附录列出来源限制；只有运行时证据才能判断某次流程是否真正发生。

## 数据结构与验收边界

`recap_backbone.segments` 保存已排列段落、源条目索引、段内events/route、源动作和错误。顶层events依旧代表原任务路线，因此此样本顶层events为空，并不表示新主干没有事件。覆盖记录通过指针引用段内正文。

批量状态为recap_draft，accepted=false；order_scope=recap_segment_only。它和selected_route、partial_order、inventory_only分开统计。缺口提示使用is_placeholder，不计入正文出现次数。任务审核错误、双向引用差异、额外内容限制仍在报告中，不因生成主干而清除。
