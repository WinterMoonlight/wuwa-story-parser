# 最复杂的无主干任务试验

2026-11-18选择《眠龙庭》146000002作为案例。12条任务的节点已重新从本地快照读取，比较结果见[结构清单](hardest-mainline-case.json)。

## 选择依据

|任务|节点总数|Sequence|ParallelSelect|其他复杂结构|
|---|---:|---:|---:|---|
|眠龙庭|57|12|11|2个Condition、计时、变量计算、QuestFailed|
|叩天关|56|9|3|ConditionSelector、QuestFailed|
|远赴乘霄|54|8|4|2个AlwaysFalse|

《眠龙庭》同时具有最多节点和最多并行节点，适合检验任务分支与玩法计数条件的组合。其他任务仍可能涉及独有机制，本案例的处理结果按规则适用形状复用。

## 已恢复的部分

### 单个直接流程调用

原任务节点4的Actions直接调用1/2，节点9的FinishActions直接调用1/5。它们分别包含4条开场说明和3条降水位对白。此前单流程分段规则只接受简单Sequence任务，复杂并行结构使这两段只存在于材料清单。

新增`independent_task_sequences`按直接调用、唯一引用及流程内部可解析性提取独立片段。复用现有`_flow_segment`，保留节点条件、父链、调用阶段、动作位置和Async。片段在任务中的位置继续独立记录。

### 计数条件驱动的三段对白

任务明确声明玩法146000053。其节点7、8、9分别在三个机关激活后执行`n1 = n1 + 1`。同一玩法中的节点10、11、12以`n1 == 1/2/3`为条件调用以下流程。

|阈值|流程|现有对白|
|---:|---|---|
|1|1/9|“成功了。”、“还有两个，我们先在近处找找。”|
|2|1/4|“还剩下最后一个「曜岩」。”|
|3|1/13|“这样的话……岁主应该可以脱困了。”等3句|

新增`counter_order.py`在同一玩法作用域内收集直接正向增量和相等阈值。接受唯一的第一项PlayFlow调用，按阈值建立局部调用顺序。计数器初始值保持未知，实际到达所有阈值、异步对白结束顺序和整任务插入位置均单独保留未验证标志。

规则遇到重置、负向或未知写入、嵌套回调写入、重复阈值和竞争式并行条件时放弃该局部排序。使用的排序键为已验证的数值阈值，节点编号和数据库行号仅用于来源追溯。

## 尚未打通的整体顺序

1. 根节点1的三个子节点为Sequence11、QuestSucceed3和ParallelSelect30。节点配置提供父子关系，未提供明确的兄弟执行列表。
2. 卷宗节点49位于并行分支33，解谜节点位于并行分支31。节点49直接同步调用1/16和1/7，这两段内部顺序已有依据。
3. 节点58检查节点49是否完成，但它与节点16同属Sequence57，两者执行先后同样缺少显式依据。当前证据不足以据此把全部解谜对白与卷宗对白串成一条任务路线。
4. 时间变量`time1`属于另一组解谜条件，和玩法计数器`n1`分别处于任务与玩法作用域。二者分别保留，未知初始值继续记录。

同族流程表中还存在1/3、1/6、1/10、1/11、1/12、1/14、1/15。本轮已确认的任务直接调用和声明玩法调用尚未覆盖这些状态，归属与触发位置需要继续找引用；仅凭同族名称无法确定它们都会出现在本任务中。

样本TXT目前包含51条文本事件及一个演出占位，分为原卷宗片段、两个新增直接调用片段和新增计数条件片段。各片段之间仍标明整体位置待确认。视频内部内容继续后置。

批量核对重点为已有主干和原片段顺序保持、源文本保留、新增片段来源可追溯。该案例目前完成局部通用规则扩展，整任务执行顺序仍需进一步取得任务节点调度证据。
