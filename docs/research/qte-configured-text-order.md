# 单线QTE配置的通用文本顺序

本轮按当前目标继续完善通用解析器，缺失正文和外部演出内容保留说明，优先排列已有对白。基线为`20261117_162610_505475`。

## 通用规则

新增`qte_text_order.py`，读取唯一、完整的TalkSequence声明顺序。按ID关联TalkItems，允许数组存储顺序不同于声明顺序。要求全部ID恰好出现一次、SequenceTransitions为空、所有节点为Talk或QTE，且没有选项、节点动作或条件。QTE编号只作源数据记录，代码没有任务ID、资源名或QTE编号白名单。

`Exporter(configured_text_order=True, allow_incomplete=True)`启用此阅读投影，当前回顾阅读入口已接入。严格解析和默认的普通Exporter仍保留原始QTE运行边界。存在成功/失败分支的配置继续走已验证的结果图规则，其他无法确认的结构保留缺口。

普通Talk通过既有说话人、女性分支、玩家名和文本读取逻辑输出。文字引用缺失时保留其位置及缺失记录，继续解析后续节点。连续QTE节点合并为原位操作说明，原始QTE节点完整保存在JSON，不计作对白或已执行选项。

没有对白的QTE段仍占据原ShowTalk组号，避免后续ShowTalk的相同TalkId错误对应到前一组。原始source_actions、每句source_item、QTE顺序和操作编号均保留。

## 顺序的适用前提

`configured_qte_text_order`证据记录声明的完整节点序列、普通文本序列和原始ShowTalk。`continuation_condition`明确为“QTE沿已声明的配置序列返回”。局部配置文本顺序可确认，`runtime_return_verified`、`qte_result_selected`和`all_runtime_outcomes_verified`均为false。

这是一条配置继续路径。结果未模拟，也没有证明实际游玩一定到达后置对白。视频、演出内部内容和隐含运行时分支继续后置。全任务及附录的顺序仍需独立验收。
