# B03 狂欢节21/1终端控制核查

## 标识和原错

任务114000029《昔我悲伤，今却歌唱》，回顾entry24，StateKey为`剧情_2_0_黎那汐塔主线_第三幕下_狂欢节_21_1`。

BinData SHA-256为`5dc537193e72be2673830f8bce1b4ec807644aed4487cae5a791d12275d39658`，动作数组字段6。原错为`Unsupported action: SetVar`。当前9个前缀事件已经覆盖默认所选分支全部可见正文。

代码原因为`recap_backbone.build_backbone`的两种常量写入环境都拒绝含FinishState的动作树，因此Exporter到达Talk9的SetVar时没有变量环境，抛出UnresolvedControlBoundary并保留9事件前缀。此报错可以区分为“状态操作无法执行”和“局部文本仍缺少后缀”。本项属于前者。

- TalkSequence完整划分所有节点，前两次选择的SequenceTransitions按选项文本键与上述目标完全对应。四个终端组的后继均为-1，没有另一组正文。

## 可合入的规则

建议加入独立“终端文本投影”规则，限回顾阅读导出，允许确认此段的所选配置文本已完整，同时保留运行时控制未核验。

1. 仅在最后一个同步ShowTalk上应用，后面不存在任何顶层动作。
2. 整个Talk图没有条件、QTE、未知项或嵌套状态/流程调用。Id唯一，所有JumpTalk目标有效，选择可由现有规则确定。
3. 状态操作仅允许出现在Talk节点的终端Actions，恰为`SetVar→FinishState→FinishTalk`。SetVar严格复用已有constant_write_shape，并限Self Boolean常量；三动作均同步，禁止Timeout/回调/额外字段。
4. 终端Actions不能出现在带Options的节点，禁止状态控制后的任何文本或跳转动作。
5. TalkSequence与节点列表完整对应。JumpTalk和SequenceTransitions一致，终端组仅存在-1后继。此例同一终端组有两条完全相同的-1边，比较目标集合时可以合并完全相同边，但不忽略不同边。
6. 在只读副本中以原本就明确存在的FinishTalk结束文本遍历。SetVar、FinishState保存为未执行的terminal_control_evidence；不能加入全局忽略白名单、写真实变量环境或向下一回顾段传播赋值。
7. 独立标记`selected_text_complete=true`、`runtime_completion_verified=false`、`cross_segment_propagation=false`，保留source_actions和全部四个终端原动作。如果复用status=parsed，含义只能是回顾所选文本解析完成，不能增加严格整任务成功数。

该规则不需要证明FinishState的所有引擎行为。由于原配置在任一解释下，终端控制之后都没有此段所选正文，并存在显式FinishTalk与终端序列-1，局部文本边界可独立证明。全局剧情推进仍由外层回顾顺序和未核验说明约束。

## 反例与拒绝条件

- FinishState后有JumpTalk/ShowTalk/PlayFlow，或顶层后置动作，不能套用。
- SetVar使用未知/Global/读变量值、异步、回调、整数运算，不能套用本规则。
- 先写变量再根据变量选择后续对白，必须有变量语义，不能只做终端投影。
- 跳转目标不存在、循环、隐含条件或SequenceTransitions不一致时拒绝。
- 若选中Talk12 false分支，本段文本仍完整，但不宣称随后主线已经开始，不使用false推导回顾后续是否发生。
- 本规则不覆盖B04只有FinishState且没有显式FinishTalk的情况，B04需要另行取证。
