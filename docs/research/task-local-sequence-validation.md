# 任务独有对白的局部调用顺序

本轮基线为`20261117_163557_602439`。目标是对已有正文补充可证明的局部顺序，保留未知的主干位置和中间回调内容。

## 代表案例

任务114000027《那神圣微风时常吹入》的节点24，Condition为PlayFlow，指向`剧情_2_0_黎那汐塔主线_第一幕_11_1`。该条件完成后，FinishActions先解锁传送触发器、改变实体状态，再同步调用`剧情_2_0_黎那汐塔主线_第一幕_12_1`。

两个流程在任务中各有一处引用，均未列入该任务回顾。11/1可解析出18个对白/选择事件，12/1可解析出22个。前段末尾为信标铭文，后段从对该铭文的疑问开始，文本衔接与明确调用关系一致。

回顾没有提供这两段的唯一主干锚点，因此本轮把40个事件组成局部有序片段。其在整个任务中的插入位置继续未核验。

## 通用规则

新增`task_local_order.py`，不按任务名或节点ID大小决定顺序。

1. 节点必须为ChildQuest，条件精确为PlayFlow，没有退出或失败条件。
2. 所有祖先必须为无额外条件的Sequence，父链完整且无循环。
3. FinishActions中必须只有一个PlayFlow，并且同步调用。
4. 条件流程和完成流程不同，各自只有一处任务引用，均未进入回顾。
5. 调用前中间动作只接受已核查形状的UnlockTeleportTrigger和Directly ChangeEntityState。未知动作、变量操作、异步调用或额外流程均拒绝。
6. 两段都通过现有Exporter读取，包含可阅读事件。缺失正文仍保留记录。任一段失败，整组不生成，不泄漏半段结果。

中间实体状态变化可能触发其他内容，本轮没有证明其回调全集。TXT在两段之间保留场景操作说明，JSON保留完整bridge_actions和`intermediate_callback_content_verified=false`。

## 输出与证据

`recap_backbone.task_local_sequences`保存节点、原始条件、完成调用、祖先链、两段原始动作、SHA-256、选择与事件。

每组`local_order_verified=true`，`mainline_placement_verified=false`，`runtime_executed=false`。文本记录使用`order_scope=same_node_condition_to_finish`，全局`order_verified=false`。

TXT在附录中以“局部有序对白”展示这两段，原来散列的相同所选文本不再重复显示。未选分支继续保留候选。文本顺序报告增加任务局部顺序表，原有回顾缺失定义统计保持。
