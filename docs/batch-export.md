# 主线批量导出

需要为全部任务提取候选材料、查看多项缺口和顺序验证时，使用 `python run.py export-reading-batch`。见[覆盖报告与分组阅读版](coverage-reading.md)。以下仍说明原严格模式；严格失败任务可以有单独的待核验阅读文件，但不计入严格成功。

在项目根目录运行 `python run.py export-mainline`，直接读取原始数据库，不依赖 inventory 缓存。

## 范围与目录

- 主组：QuestData.Type=1。
- 补充组：Type=15。类型表同样显示“潮汐任务”，但包含任务变体、活动和测试记录，因此不混入主组。
- 同名不同 ID 不合并。所有选中 ID 在清单中恰有一条状态。
- 每次运行创建新的时间戳目录，避免旧成功文件与新失败状态混淆。

```text
outputs/主线批量/<运行时间>/
  导出报告.md
  导出清单.json
  暂不支持任务.json
  主线_Type1/<章名>/<章节配置ID_幕名_幕标题>/<任务ID_任务名>.json
  主线_Type1/<章名>/<章节配置ID_幕名_幕标题>/<任务ID_任务名>.txt
  补充潮汐任务_Type15/…（有成功任务时生成）
```

章幕归属来自 QuestData.ChapterId → db_quest_chapter.questchapter.Id。当前快照 BinData 字段 1～4 对应 ChapterNum、SectionNum、ActName、ChapterName 文本键。QuestTree 的 ChapterId 属于另一套章节树，不直接与此 ID 混用；树成员关系单独保留。没有章节配置的任务归入“未关联章节”。任务 ID 排序只为方便归档，不代表剧情先后。

## 成功与失败标准

沿用单任务导出器的保守验证。仅在受支持任务形态完成、选定路线有事件且文本引用无缺失时写出一对任务文件。遇到暂不支持的控制结构、条件或动作，记录异常并继续下一任务，不把已解析的半段对白作为完整任务输出。

报告记录首次失败原因、中文所缺能力以及静态节点/条件/任务动作特征。首次失败可能遮挡后续问题，因此不能将它当成该任务的全部待办。源库 SHA-256 和 BuildInfo 保存在导出清单中。

阅读正文继续统一玩家名“漂泊者”、Female 分支和女性 TA，JSON 保留原文。

## 当前快照实测

共处理 135 个候选：Type=1 为 85 个，成功 2 个（行路遇新知、撞金止行阵）、失败 83 个；Type=15 为 50 个，均暂不支持。

初版首次阻塞为 109 个任务图、15 个条件、10 个动作；复杂回顾任务扩展后，这些历史统计已失效，以最新批次报告为准。后续待完善：

1. ParallelSelect、ConditionSelector、Repeater、失败分支等控制结构与子节点顺序，不能简单按编号遍历。
2. ReachArea、CheckConditionGroup、Kill、CheckEntityState、FinishDungeon、CompareVar、Timer 等条件的状态假设及关联。
3. 任意任务节点动作列表中的 PlayFlow、变量修改、实体分组和副本切换。不能跳过可能改变剧情路线的动作。
4. 在上述结构可达后，再核验跨状态跳转、循环对话、流程覆盖和任务间前后关系。

测试覆盖失败后继续、候选状态划分、成功文件成对、失败不产生任务文件、章节信息一致、女性渲染，以及混合数值/字符串条件的报告。原有单任务分支和身份解析测试保留。

## 多阻塞点诊断与开发接续

运行 `python run.py scan-mainline` 可同时列出各任务已识别的未知动作与外部内容调用，不受批处理首次异常短路影响。它仍是静态诊断，不证明所有分支均可运行。下一步先处理万象新声·下的视频字幕和任务提示，详见[任务计划](history/task_plan.md)及[研究结论](history/findings.md)。
