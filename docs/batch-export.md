# 批量导出与连读

在项目根目录运行 `python run.py export-reading-batch`。程序直接读取 ConfigDB，每次运行创建新的时间戳目录。

```text
outputs/主线批量/<批次>/
  导出清单.json
  导出报告.md
  暂不支持任务.json
  覆盖阅读版/
    主线连读索引.md
    主线阅读报告.md / .json
    覆盖报告.md / .json
    文本顺序报告.md / .json
    剩余阻塞.md / .json
    Type1/<章>/<幕>/<任务ID>_<任务名>.txt
    Type1/<章>/<幕>/<任务ID>_<任务名>.json
    Type15/...
```

- **按剧情通读** 打开 `主线连读索引.md`，从序幕点击任务名。索引使用前置条件、已核对的总回顾和章节树。
- **看单项阅读状态** 打开 `主线阅读报告`。它统计 TXT 实际显示的文本。
- **诊断缺口和重复** 打开 `覆盖报告`、`文本顺序报告` 或 `剩余阻塞`，对应证据在同任务 JSON 内。

## 任务与目录

Type1 是本批导出的主线候选范围。Type15 单列，用于保留补充记录。同名不同 ID 的任务分别导出。章幕目录来自 `QuestData.ChapterId` 到 `questchapter.Id` 的关联，未匹配到章幕的记录保留在 `未关联章节`。任务 ID 是文件标识，阅读先后由索引提供。

## 严格检查与覆盖阅读版

`export-mainline` 只执行严格批量检查。受支持的选定路线在配置检查和文本引用检查通过后才写出文件。其它记录保留首次失败原因和配置特征。

`export-reading-batch` 先生成该严格结果，再为各任务构建覆盖阅读版。严格流程失败后仍可从回顾和有证据的调用中得到阅读稿。批次清单保存数据库哈希和版本信息，可用于复查和比较。实际验证范围见[当前状态](status.md)，字段和区分方式见[覆盖报告说明](coverage-reading.md)。
