# 仓库与本地数据管理

源码仓库已公开：[WinterMoonlight/wuwa-story-parser](https://github.com/WinterMoonlight/wuwa-story-parser)。公开范围为下文所列源码与文档，原始数据和完整语料继续在本地管理。

## 提交范围

仓库提交解析器、测试、维护脚本、文档和虚构格式示例。`ConfigDB/`、`outputs/`、`work/`、`.codex/`、虚拟环境、构建产物与缓存由`.gitignore`排除。

原始数据库、游戏客户端脚本、演出资产和完整导出语料由使用者在本地管理。公开仓库的可见性不改变这些文件的提交范围。项目没有自动上传数据的步骤。

## 许可证

[MIT 许可证](../LICENSE)仅适用于本项目原创的解析器源码及配套文档。游戏数据库、客户端文件、游戏资产和剧情导出保存在本地，相关权利由各自权利人保留。文档中的第三方内容及参考资料沿用原许可或权利声明。WuwaID 对照命令使用的参考文件保存在本地。其许可证见[第三方许可记录](third-party/WuwaID-LICENSE.txt)。

## 发布检查

1. 运行语法、链接和无数据库测试；有数据的环境再运行完整回归。
2. 检查`git diff --cached`和实际跟踪文件，不把`.gitignore`当作历史清理工具。
3. 检查所有将公开的历史提交：凭据、个人路径、数据库、客户端文件和完整导出语料。
4. 验证包中只包含`wuwa_story`源码，CLI帮助不依赖游戏数据。
5. 提交、推送后核对远端提交。改变仓库可见性作为独立步骤执行。

## 文件生命周期

|目录|用途|清理原则|
|---|---|---|
|`ConfigDB/`|原始输入|保留，同版本成套管理|
|`work/asset_exports/`|用户提供的资产属性|保留，不能当缓存删除|
|`work/client-scripts/`|用户提供的辅助研究输入|保留，不提交|
|`work/maintenance/`|清理清单和本地发布审计|保留本次操作记录|
|`outputs/主线批量/`|可重新生成的导出批次|保留最新成果和需要的对照批次|
|`docs/history/`|已归档规划|保留文字记录，避免根目录膨胀|
|`__pycache__/`等|解释器缓存|可删除|

普通ZIP打包不会读取`.gitignore`。若分发源码，使用Git导出或检查压缩包清单；需要搬运数据库时单独复制并核对哈希。
