# 批量覆盖报告与分组阅读版

在项目根目录运行：

```powershell
python run.py export-reading-batch
```

命令先运行原有严格批处理，再在同一批次的 `覆盖阅读版/` 中为所有 Type=1/15 任务分别输出 JSON、TXT。原有严格成功判定不变；两个目录用途不同，不要把阅读版文件数当作完整成功数。数据库只读，历史批次不覆盖。

入口为 `覆盖报告.md`，详细机器报告为 `覆盖报告.json`。每个任务按章节归档，保留同名不同 ID。章节内文件排序不是剧情时序。当前数据可能包含测试、旧版及未开放任务。

## 四类内容

|分类键|含义|能够证明什么|
|---|---|---|
|confirmed_route|已完成解析的所选配置路线|当前解析器支持的回顾/显式流程顺序；不证明完整游戏运行时顺序|
|candidate_branch|未纳入所选路线的可选回应及选项内材料|配置中存在该选项；不证明它能到达或必定播放|
|failure_ending|失败父链独占引用，或只关联失败结局的卡牌材料|存在失败关联；不代表本次阅读路线失败|
|unverified|其他静态对白、界面、手机、小游戏与共享结局材料|成功提取到材料；实际触发、时序或路线仍待核验|

分类采用保守证据。成功与失败共享的卡牌不归入失败专属类。失败分支中的选项保留失败分类。未知角色不推测身份；静态对白仍按本条WhoId读取配置姓名，无法确定时保留问号。普通玩家选项、画面文字与QTE结果独立标识，不借用祖先NPC姓名。详见[姓名修正](batch-speaker-validation.md)。

## JSON 和 TXT

任务 JSON 继续保留 `events`、原始配置及已有审计字段，新增 `batch_coverage`：

- `strict_pass`：原严格批处理是否通过。
- `status`：`selected_route` 或 `inventory_only`，均不是“完整剧情”的承诺。
- `counts`：四类可读文本出现次数，不是去重台词数，也不是完整率。
- `source_counts`：所选事件、静态流程文本、已解码外部调用、手机事件、小游戏正文和界面引用数量。它们并非互斥，不应相加计算总台词。
- `order`：分别说明所选配置路线、回顾引用集合、运行时及跨任务顺序的验证状态。
- `records`：逐项分类及原始路径，或指向任务 JSON 的指针。原始外部记录仍完整保留。
- `gaps`：逐项记录流程缺失、未知动作、引用差异、外部调用错误、文字缺失和时序问题。
- `task_conditions`：条件原配置，不能视为已执行。

TXT 只显示分类标题、正文、选择和简短缺失说明。不会展示节点、变量、动作路径或异常堆栈。小游戏候选与结局正文保留，不能把其排列读作一条成功游玩路线。

## 提取策略及限制

先尝试允许待核验内容的完整路线导出。若失败，丢弃该解析实例中的全部半成品事件，重新扫描任务及回顾显式引用的流程。只在选中状态与文字 ID 匹配时省去已输出的静态文本，这种过滤不是分支可达性证明。

每个流程单独检查，因此不会在首个未知动作处结束整个任务的诊断。顶层外部调用独立解码，单个错误不会隐藏后续调用。独立解码会记录原始动作位置及前序动作；临时数组索引不代表原始时序。嵌套外部调用尚未独立求值，单列缺口。

静态遍历顺序仅供材料归档；既不等同于播放顺序，也不保证全库所有有关文字都已找齐。未选分支对白通常保留在未核验类；本版尚未完整复原分支图。媒体可能携带额外字幕，UI、邮件及小游戏数值规则仍受现有解码能力限制。报告列出已观察到的问题，不承诺穷举所有潜在问题。

## 回顾主干草稿（2026-11-17）

新增 `recap_draft` 状态。完整任务解析失败但存在唯一回顾列表时，`recap_backbone.segments` 按回顾条目顺序保存每段 `events`、`route.choices`、动作/身份来源和缺口；`entry_index` 保留原列表位置。顶层 `events` 仍只表示原已验证任务路线，可能为空；不要因此误认为回顾主干无正文。

逐段使用独立解析状态，段内失败不保留半条路线；`recap_gap` 位于原段落位置，缺口占位不计正文数。主干的覆盖记录使用 `order_scope=recap_segment_only`，即使列在confirmed_route分类，也不证明整个任务实际播放顺序；全任务 `selected_route_verified=false`、`reading_acceptance.accepted=false`。TXT先展示主干，再展示尚未归位/未选择材料，不再把主干选择抽离对白。

`duplicate_text_flows` 只记录非回顾来源与现有材料完整文字序列（含文本键、类型、说话人）一致的情况。`text_duplicate_of` 让TXT省略重复展示，JSON保留来源；不表示动作等价，不折叠回顾中重复出现的位置。当前批次60个回顾草稿；全文仍需检查缺段、未定位流程及运行时条件。详见[回顾主干验证](echoes-recap-validation.md)。
