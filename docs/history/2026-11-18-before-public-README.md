# 鸣潮剧情解析

从 FModel 导出的 ConfigDB 还原任务对白，生成按任务和章节组织的 JSON 与 TXT 基础语料。解析器保留文本来源、选择、说话人和缺口，阅读版支持女漂泊者与统一玩家名“漂泊者”。

当前优先导出可连续阅读的主线剧情，核对关键对白、必要结果、选择衔接和重复。复杂活动内部的小分支、小玩法可按主线需要省略。视频内部字幕及尚未取得的演出内容后置，媒体调用在对应位置保留记录。批量输出新增文本顺序报告，区分条件路线、外部内容、缺失定义和未确认顺序。

当前交付验收关注所选主线能否按配置顺序读通。复杂活动保留必要剧情与前后承接，原始对白及技术证据保存于JSON。缺失正文、流程和媒体内容暂存记录，开发优先处理已有对白的调用顺序、选择后续与重复。下表的严格整任务通过数保留历史完整性口径，后续进展重点报告已有文本的排序情况。

## 当前开发方向

以现有ConfigDB为主要输入，沿任务与回顾入口查找流程，关联文本和说话人，再根据已确认的调用关系组织选择与对白顺序。任务调用、实体与玩法依赖、回顾顺序按已有证据共同参与还原。

后续优先解决数据库引用漏扫、分支错接、重复输出和已有文字的排序问题。先在代表任务验证，再检查批量结果。JavaScript调查作为辅助参考归档，当前工作继续使用已导出的数据库推进。视频与演出内部内容、复杂活动细节继续后置。知识库与知识图谱留作后续独立项目。

## 快速开始

需要 Python 3.10+。运行时使用标准库，当前数据验证环境为 Windows / Python 3.13。

```powershell
git clone https://github.com/WinterMoonlight/wuwa-story-parser.git
cd wuwa-story-parser
```

将同版本完整 `ConfigDB/` 放到项目根目录，保留 `zh-Hans/` 与 `Misc/` 子目录。外部数据库可通过环境变量配置。

```powershell
$env:WUWA_CONFIG_DB = 'D:\GameData\ConfigDB'

# 按章节生成全部任务、覆盖报告和阻塞清单
python run.py export-reading-batch

# 单任务阅读草稿
python run.py export-recap --quest-id 139000027 --output outputs/sample
```

批量结果位于 `outputs/主线批量/<批次>/覆盖阅读版/`，每任务一份 JSON 和同名 TXT。输入结构见[数据库说明](../database-guide.md)。

## 输出内容

- JSON 保存原文、文本ID、动作和条件、身份来源、所选路线与验证状态。
- TXT 展示对白、选择、小游戏文本与简短缺口说明，未定位内容带有范围说明。
- TXT 统一去除颜色、术语链接、加粗等富文本标签，保留显示文字、注音说明与显式换行。JSON保留源文字和标记。
- 手机表情和图片附件保留位置及资源编号，按媒体引用记录；其占位文字键缺失时按图片处理。
- 任务目标、角色占用提示和系统按钮标签按配置来源从TXT排除，原始记录留在JSON中；对白中的相同字句和剧情选择保留。
- 姓名按配置关联。明确空名称显示“无署名”，匿名人物保留问号。
- 阅读顺序优先采用已确认的任务调用与触发依赖，回顾作为补充。原始数据库以只读方式访问。
- 原始数据、生成语料、临时研究文件及本地技能由 `.gitignore` 排除，换机时单独恢复。

格式定义见[语料格式](../corpus-format.md)，当前工具能力和限制见[架构](../architecture.md)。
