## 阅读版验收标准（2026-11-17调整）

1. 每任务一个JSON/TXT，身份不明保留问号，女漂泊者和原文证据规则不变。
2. 正文顺序必须有回顾配置或已验证依赖证据；不能按ID或文件顺序猜测。选中分支前后一致，QTE结果不冒充普通选择。
3. 关键正文、未知分支与未核实时序显式标记；附录候选、失败分支与主体分开。只有静态材料的文件不算有序正文。
4. 可读取的配置路线不等于运行时完整；有序正文也不自动算已验收。章节连读、关键缺段、重复、衔接和来源核对完成后才标记阅读验收通过。
5. 允许明确形状的表现/世界状态动作仅记录不执行，但必须保留参数与完成假设；它们可能影响游戏可达性，不能声称无运行时影响。未知字段、剧情/条件/动作嵌套仍拒绝。
6. 指标分开记录：有序配置路线数、仅候选数、实际阅读验收通过数、关键缺口。严格模式原标准保留。暂不以逐帧、小游戏完整模拟作为阅读版通用前提。

本轮步骤：参数清点→收紧/扩展已核实形状→首个错误前后对比→新增任务抽查→测试/全批次→更新进度。若没有新增路线，明确报告0并记录新的共同阻塞。

## Decisions

1. 面向通用机制开发，不写任务 ID、人物名专用解析规则。
2. 未知身份保留问号。用户明确否决场景专属的 849→鉴心校订；没有实施这种映射。
3. 显示名与解析身份分开；只有明确配置证据才关联身份。849 是复用显示标签，不能作为全局人物身份。
4. 第一次选第一个无条件选项；循环菜单重访选择未选项直至退出。普通互斥分支不全部拼接。
5. 固定女性分支、PlayerName→漂泊者、TA→她；raw_text 和源配置保持不变。
6. 回顾配置可作为阅读顺序依据，不宣称模拟了游戏任务运行时。
7. 缺少关键支持时明确失败；不得通过忽略可能携带剧情的动作提高“成功率”。
8. .codex、ConfigDB、outputs、work 继续 Git 忽略；三份计划文件和 docs 应随源码提交。
